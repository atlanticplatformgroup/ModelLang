# ModelLang 0.45 extension-backed agent tool adapters

## Outcome

ModelLang 0.45 makes declared external extensions callable through generated HTTP and MCP adapter surfaces without pretending to implement them. Catalog v7 publishes a separate extension-tool collection, MCP adapter v5 registers the same exact contracts, and generated HTTP code exposes typed client methods plus a request-bound host runtime interface.

The host must register the exact opaque contract revision, authorize every invocation, implement the external behavior, validate its own downstream trust boundary, and own effects, retries, evidence, tests, deployment, and monitoring. ModelLang validates the transport contract and fails closed; it does not verify the host assertion.

## Threat model

An MCP client may discover or invoke an extension tool but cannot supply caller identity, ModelLang command metadata, or a delegated capability credential. Discovery grants no authority. Missing or revision-mismatched adapters return unavailable, host denial returns unauthorized, invalid inputs are rejected before the host boundary, and invalid host results are not disclosed.

Extension results use a no-store, non-authoritative object envelope. They are executable tool results, not query-backed current-state resources, so they carry no point-in-time resource freshness contract and produce no MCP embedded resource.

## Contract changes

- compiler and examples: 0.45.0;
- canonical IR: IR1, unchanged;
- agent catalog: v7;
- MCP adapter: v5;
- extension tool result: v1;
- target capability profile: v9;
- target: `target:postgresql-http-ui-extension-tools/9`;
- generator: `postgresql-http-ui-extension-tools/29`;
- operation, capability, resource, subject-view, task-packet, delegated-capability, public-trace, UI, semantic, event, diff, provenance, and extension-ledger versions: unchanged.

## Conformance boundary

The private extension ledger remains v1, `public: false`, `executable: false`, and `generatedImplementations: 0`. The Procurement target remains `requiresExternalImplementations`; its supplier-risk gap is not closed by an adapter or test fixture. Live integration coverage proves that a host implementation can compose with generated authentication and real PostgreSQL state, not that ModelLang generated or verified the external implementation.

## Deferred work

Adversarial agent testing and stronger SML-Agent evaluation are next. Dynamic extension negotiation, delegated extension authority, generated implementations, host attestation, extension resources/subscriptions, complete task closure, and full SML-Agent conformance remain future work.
