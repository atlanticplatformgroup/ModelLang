# ModelLang 0.34 authored sort profiles plan

Status: implemented in the 0.34 reference compiler.

## Goal

Let a query author expose a small closed set of useful orderings without opening a caller-controlled SQL, field, direction, limit, or pagination surface. The existing required `orderBy` remains the default and queries without profiles retain their prior ABI.

## Contract

Named `sort profileName: row.field asc|desc;` clauses appear between `orderBy` and `limit`. Names are query-local, unique, and capped at 16; `default` is reserved. Each profile targets one required direct source-row field. The source identity is always appended ascending as the deterministic tie-breaker.

A query with profiles receives optional input `sort`, closed to `default` plus the authored names. The operation, OpenAPI, HTTP, TypeScript, UI, and semantic contracts all derive that same allowlist. Profile selection changes ordering only: it grants no authorization, row access, projection member, limit, or snapshot guarantee.

## Execution

IR23 records stable query-scoped profile identity, field identity, direction, and the fixed identity tie-breaker. PostgreSQL lowers the profiles to static `CASE`-guarded ordering and keyset predicates. It validates the input before scanning and never uses dynamic SQL. The TypeScript database client passes the selected name as a value, and the generated HTTP boundary performs the same exact enum validation.

Cursor payloads carry the active field identity and direction; the selected profile is also part of the cursor input fingerprint and pagination revision. Cross-profile reuse therefore fails with `ML_STALE:cursor:<query-id>` before disclosure.

## Evolution and verification

Adding a profile is additive. Removing one or changing its selected field or direction is breaking; paginated contract changes also revise cursor compatibility. Verification covers parser/type rejection, IR and enforcement evidence, static PostgreSQL lowering, exact manifests and schemas, transport validation, UI metadata, semantic diff, deterministic goldens, and live default/ascending/descending traversal plus cross-profile cursor staleness.
