# ModelLang 0.32 cursor pagination plan

Status: implemented in the 0.32 reference compiler.

## Goal

Add deterministic continuation to authored read queries without introducing offset semantics, caller-selected limits, runtime sorting, or cursor authority. Existing queries remain array-returning unless they explicitly declare `paginate cursor;` after their fixed limit.

## Contract

A paginated query accepts one generated optional `cursor` input and returns the closed object `{ items, nextCursor }`. `items` is bounded by the authored limit. `nextCursor` is either an opaque base64url string or `null`; callers cannot supply a page size.

The cursor payload binds cursor format version, model ID and version, model source hash, query stable ID and semantic revision, ordering field and direction, authenticated principal, callable filter inputs, last sort value, and last entity identity. Malformed payloads raise `ML_VALIDATION:cursor:<query-id>`. Structurally valid cursors whose bindings no longer match raise `ML_STALE:cursor:<query-id>`.

## Execution

PostgreSQL re-resolves identity, callable entity parameters, query authorization, and row policy on every page. It uses a strict keyset predicate over the authored required order field plus ascending UUID identity, reads at most `limit + 1` rows, returns at most `limit`, and emits a continuation only when another row exists. Generated query SQL contains no `OFFSET`.

The cursor is opaque transport state, not a signature, capability, or authorization artifact. Altering it cannot widen visibility because all authority and row predicates are re-evaluated and cursor fields are validated against compiler-owned constants and the current input fingerprint.

## Derived artifacts

IR21 adds an optional cursor pagination descriptor and deterministic query revision. Operation manifest v7, UI manifest v7, and semantic manifest v13 distinguish page output from legacy array output. OpenAPI, TypeScript clients, HTTP validation, UI execution types, migrations, provenance, and semantic diff v14 carry the same contract. Capability manifest v6 tracks operation manifest v7 without exposing cursors as authority.

## Verification

Conformance covers deterministic lowering, exact schemas, fixed bounds, absence of offset SQL, principal/filter binding, multi-page traversal without gaps or duplicates, malformed rejection, stale rejection, unchanged unpaginated arrays, deterministic golden generation, live PostgreSQL integration, demos, and full static quality gates.
