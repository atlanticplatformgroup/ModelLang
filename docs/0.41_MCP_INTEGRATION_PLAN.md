# ModelLang 0.41 direct MCP integration

## Goal

0.41 exposes the existing stable agent contracts through MCP without creating a second authorization or execution system. Catalog discovery remains metadata; PostgreSQL-backed runtime enforcement remains authoritative.

## Implemented contract

- MCP adapter manifest v1 binds every catalog v3 action and query to a stable MCP-compatible name and the catalog's exact JSON Schema 2020-12 input/output documents.
- A generated stateless Streamable HTTP handler uses the official MCP server interface and protocol revision `2026-07-28`.
- The host verifies bearer tokens for every request and supplies audience-bound `AuthInfo` plus an executor already bound to the verified identity.
- Actions use the existing operation executor and accept revision, idempotency, correlation, and causation only as namespaced MCP request metadata.
- Queries use that same executor and return both exact structured output and an embedded resource envelope v1 with zero-age, revalidate-before-reuse, and no-store semantics.
- Discovery is static, unfiltered, and non-authoritative. No protocol response grants authority, and every invocation rechecks current runtime rules.
- Safe protocol errors disclose only allowlisted ModelLang failure codes and rule IDs.
