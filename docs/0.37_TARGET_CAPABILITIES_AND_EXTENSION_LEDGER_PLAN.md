# ModelLang 0.37 target capabilities and extension ledger

Status: implemented.

## Outcome

0.37 makes unsupported and handwritten behavior visible without pretending to generate it. A typed `extension` declaration records a stable contract, effects, ownership, implementation, reliability, authorization context, tests, rationale, and promotion criterion. It is engineering assurance metadata only.

Every build emits a deterministic extension ledger and a canonical target-capability assessment. Current core semantics are reported as native. Each extension is reported as an explicit external implementation gap, making target conformance honest and machine-checkable.

## Locked boundaries

- Extension declarations are never callable from generated operations and grant no authority.
- Public operation, capability, OpenAPI, UI, SQL, and client artifacts omit extensions.
- The current canonical IR and semantic manifest v18 retain the full trusted declaration.
- Provenance v2 identifies `target:postgresql-http-ui/1` and hashes both assurance artifacts.
- Semantic diff v19 tracks extension identity, contract, behavior, and governance.
- No PostgreSQL object or operational upgrade is introduced; runtime profile remains 36.
- Alternate target generators and runtime extension conformance remain deferred.
