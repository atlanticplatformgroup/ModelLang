# ModelLang 0.39 authenticated subject capability views

## Goal

0.39 makes static agent action discovery useful for one authenticated subject without widening runtime authority or exposing current resource state. The generated HTTP boundary accepts exact action candidates and returns a minimal overlay derived from the same PostgreSQL applicability functions used by ordinary preflight.

## Implemented contract

- Agent catalog v2 declares the authenticated, subject-specific `POST /agent/capabilities` overlay and keeps the complete static tool list unchanged.
- Requests contain at most 32 distinct action candidates with exact closed action input and an optional opaque revision. Query-only models accept an empty set; query tools otherwise remain static-catalog-only.
- The generated server authenticates first, validates the closed request, rejects command metadata, and assesses candidates in order without executing them.
- Subject view v1 returns only model identity and action outcomes keyed by stable ID. It does not echo identity, input, resource state, expressions, extensions, or private evidence.
- Generated OpenAPI, browser-safe HTTP clients, response schema, target capability assessment, deterministic provenance, unit tests, and live PostgreSQL gateway tests cover the contract.

## Safety boundary

Every returned entry has `authority: "none"`. The collection is not atomic and has no promised freshness lifetime. Later execution resolves identity and state again and remains the sole authoritative enforcement boundary. Revision comparison can reject stale input but cannot grant authorization.
