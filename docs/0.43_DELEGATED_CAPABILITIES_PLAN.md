# ModelLang 0.43 delegated capabilities

## Outcome

ModelLang 0.43 adds deliberately narrow delegated authority over the existing stable action contracts. A grantor can authorize one named authenticated delegate to invoke one exact action with one exact input, at one audience, once, within at most one hour. The grant is revision-bound, non-transferable, non-redelegable, revocable, and re-enters the normal runtime enforcement path.

## Threat model

The design assumes discovery metadata, task packets, and resources are untrusted planning inputs and never authority. A delegated credential is secret but is insufficient alone: the request must also authenticate the named delegate through the normal bearer lifecycle. The host owns credential entropy, secure storage, identity binding, revocation, and atomic consume-and-execute. The generated boundary owns closed schema validation, exact canonical input hashing, model/catalog/audience/time/constraint validation, rejection of caller command metadata, and dispatch into the authoritative action executor.

The contract limits blast radius through exact action and input binding, a required concurrency revision, one use, a one-hour maximum lifetime, a fixed audience, no transfer, and no re-delegation. It intentionally does not introduce wildcard scopes, delegation chains, refresh, general roles, or bearer-only capability tokens.

## Boundaries

Issuance and revocation are authenticated HTTP management operations. HTTP action invocation uses `delegated-capability`; MCP action invocation uses `_meta["dev.modellang/delegatedCapability"]`. MCP does not expose issuance as a tool. Queries and resources remain reads, actions remain commands, and neither catalog nor MCP discovery grants authority.

Generated adapters require a host credential authority callback. This is an explicit conformance boundary, not a generated cryptographic or persistence implementation. The live PostgreSQL coverage demonstrates that delegated calls execute as the stored grantor and retain database policy, revision, workflow, audit, and output semantics; it does not claim a production distributed credential store.

## Deferred work

Agent task goals and richer task packets, public decision traces, extension-backed agent tools, adversarial agent testing, broader SML-Agent evaluation, transferable or chained authority, and general MCP resources/prompts/subscriptions remain future work.
