# ModelLang 0.31 bounded to-one traversal

Status: implementation plan for the 0.31 release.

## Outcome

ModelLang 0.31 lets a named read projection explicitly replace a direct entity-reference UUID with one nested named projection. Traversal remains a closed, compile-time-authored disclosure contract: it is to-one only, projection dependencies must be acyclic, and callers cannot select paths, depth, fields, sorting, or limits at runtime.

## Surface language

```modellang
projection UserSummary from User {
  id;
  name;
}

projection RequestSummary from PurchaseRequest {
  id;
  approvedBy: UserSummary;
}
```

A member without `: ProjectionName` retains the 0.30 behavior. In particular, a direct entity reference remains its UUID. A member with `: ProjectionName` must select a non-collection entity reference, and the nested projection source must be that referenced entity.

## Closure and authority

- The projection dependency graph must be acyclic. Its finite authored closure is the traversal bound.
- Public manifests include the transitive dependency closure of every query result projection and exclude unrelated projections.
- Query authorization and root-row policy remain authoritative. A nested projection grants no independent authority; selecting it in the root result explicitly discloses that related shape.
- Optional references encode the required JSON key with an object or `null`. Required references encode a non-null object.
- Missing referenced rows are prevented by generated foreign keys. No implicit outer collection, fan-out, or silent redaction is introduced.

## Canonical and derived contracts

IR20 adds optional `nestedProjectionId` to a projection member. Operation manifest v6, UI manifest v6, and semantic manifest v12 expose the same dependency edge. OpenAPI uses nested projection `$ref` values, generated TypeScript uses nested interfaces, HTTP validation recursively validates closed objects, and PostgreSQL uses correlated primary-key lookup while constructing only authored JSON keys.

The semantic query read/disclosure closure includes every traversed reference and every transitively selected field. Mermaid and enforcement evidence distinguish source-row reading from nested projection disclosure.

## Evolution

Adding, removing, or changing `nestedProjectionId` on an existing reachable member is breaking. Reachability is transitive for safe-migration checks: changing a nested dependency used by a query requires reviewed migration even when it is not a query's root projection. IR9 through IR19 remain accepted evolution baselines; missing `nestedProjectionId` means the historical direct-field contract.

## Non-goals

Collections, reverse relationships, joins not rooted in a declared entity reference, projection cycles, runtime-selected depth, inline anonymous objects, aliases, nested authorization, optional filters, pagination, aggregates, freshness, and MCP generation remain outside 0.31.
