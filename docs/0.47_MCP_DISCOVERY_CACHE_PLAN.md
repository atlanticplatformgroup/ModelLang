# ModelLang 0.47 MCP discovery caching

## Outcome

ModelLang 0.47 makes the new stateless MCP discovery cache contract deployable without weakening the current-state or authority boundary. A developer may select how long the generated static server/tool description remains reusable. The default stays zero and all business-state and execution responses stay no-store.

## Contract

- cacheable MCP methods: `server/discover` and `tools/list` only;
- handler option: `discoveryCacheTtlMs`, a non-negative safe integer in milliseconds;
- scope: private, because MCP remains authenticated per request;
- invalidation identity: deterministic SHA-256 revision over the exact static discovery contract, exposed as `ETag`;
- HTTP variation: authorization plus MCP protocol/method/name headers;
- zero TTL: `no-store`;
- positive TTL: private HTTP `max-age` plus exact MCP `ttlMs`;
- every tool call: fresh authentication and authoritative runtime enforcement.

## Version axes

- compiler and examples: 0.47.0;
- MCP adapter: v6;
- generator: `postgresql-http-ui-mcp-discovery-cache/31`;
- canonical IR1, catalog v7, target profile v9 and target `/9`, assessment/evaluation formats, and runtime envelope versions: unchanged.

## Deferred work

Model-authored freshness, shared/public discovery caches, push invalidation, CDN management, and nonzero current-state reuse remain out of scope. Those features require separate disclosure and staleness semantics rather than a transport cache switch.
