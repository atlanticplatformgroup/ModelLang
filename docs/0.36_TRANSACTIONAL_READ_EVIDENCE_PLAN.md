# ModelLang 0.36 transactional read evidence plan

Status: implemented in the 0.36 reference compiler.

## Goal

Let model authors opt sensitive queries into durable, privacy-minimized evidence without changing public result shapes or copying result data into an audit store. State the transaction boundary honestly: only successful committed invocations have durable evidence.

## Contract

Terminal `audit reads;` adds IR25 transactional-audit mode and a deterministic query revision. The operation, OpenAPI, UI, semantic, enforcement, and provenance artifacts publish the static guarantee, hash profile, private storage, payload-free retention, and revision. The query gains no input and returns the same array or cursor page as before.

PostgreSQL inserts one private record after exact result construction. It binds model/query identity and revision, direct or gateway identity, canonical request SHA-256, exact response SHA-256, result count, sort profile, and continuation state. No raw inputs, cursor, response, or row value are persisted. Failure or denial writes nothing; caller rollback removes the evidence.

## Execution and migration

Fresh schemas create `query_audit` under owner-only internal privileges and record private runtime profile 36. Baseline-checked `020_upgrade_0_36.sql` creates the table, regenerates query functions, advances the monotonic runtime ledger, and fabricates no history. Older operational upgrades refuse to redeploy over profile 36.

## Evolution and verification

Adding or removing audit mode is breaking with persistence risk, and audit mode participates in cursor revision identity. Since 0.38, evolution inputs must carry the current explicit read-evidence contract.

Verification covers parser/IR lowering, schema-valid manifests, OpenAPI/UI/semantic metadata, static SQL, payload absence, unaudited-query non-writing, exact request/response hash parity, direct and gateway identity attribution, private-table denial, failure non-writing, rollback, idempotent upgrade replay, downgrade rejection, deterministic goldens, and live PostgreSQL execution.
