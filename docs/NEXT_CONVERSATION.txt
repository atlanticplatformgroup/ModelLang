Released 0.18 architecture
--------------------------

- Canonical IR10 adds stable reusable policies, typed parameters, stable authority branches, and identity-based policy calls.
- Policy v1 is pure Boolean and closed. Exactly one true `allow` branch succeeds; zero or multiple true branches fail closed and null never grants authority.
- Policies may compose acyclically. Recursion, effects, callbacks, dynamic selection, and backend syntax are prohibited.
- Action authorization may contain at most one positive conjunctive policy call. The unique successful branch is exact executed authority.
- Decision plan v2 is the one internal expression-bearing input to both applicability and execution.
- Applicability remains authenticated, pure, advisory, and public-safe. Every response still carries `authority: "none"`.
- Capability manifest v1, operation manifest v2, UI manifest v2, and HTTP routes remain unchanged and expose no policy IDs, expressions, evidence, or current facts.
- Successful action execution privately records model/source identity, action and authorization rule IDs, executed outcome, and exact policy/branch authority when present.
- Evidence, effect, and action audit share one transaction. Failed or rolled-back execution leaves no success evidence.
- Historical pre-0.18 audit rows remain evidence-unknown; authority is never reconstructed from role snapshots.
- Engineering semantic manifest v2 reports policy use and applicability/execution/evidence coverage.
- Semantic diff v3 compares policies and branches by stable ID. Safe migration permits identity-preserving renames but not semantic policy changes; reviewed migration requires explicit acknowledgements.
- IR9 remains accepted as a released evolution baseline when the current source compiles to IR10.
- `008_upgrade_0_18.sql` is the baseline-checked idempotent evidence-boundary upgrade.

Semantics that remain locked
----------------------------

- Entity equality is primary-key identity equality.
- Caller identity comes only from authenticated context and is never caller input.
- `@snapshot` is explicitly assigned stored point-in-time data.
- Money is exact and currency-typed.
- Generated UUID/timestamp fields are database-owned.
- Durable declarations have stable semantic IDs.
- Workflows bind legal state transitions to actions.
- PostgreSQL is the first enforcement backend; canonical IR is the backend boundary.
- Discovery, applicability, and execution are separate.
- `authorize` failure is denied; `require` failure is notApplicable.
- Missing and invisible entity references share authorization denial by default.
- Public explanations contain only allowlisted stable action-rule IDs.
- Execution locks, reloads, and re-evaluates the canonical plan inside the mutation transaction.
- Applicability, opaque revisions, policy IDs, authority IDs, and audit evidence grant no authority.
- `stale` requires an explicit expected revision comparison.
- Generated artifacts are committed golden fixtures and remain byte-for-byte synchronized.

Verification contract
---------------------

Before the next release run:

- npm run build
- npm run model:check
- npm test
- npm run demo
- npm run demo:reservations

Do not begin MCP or agent generation by exposing `decisions.json` or private evidence. Any future agent-facing contract must be a separately filtered, authorization-aware projection.
