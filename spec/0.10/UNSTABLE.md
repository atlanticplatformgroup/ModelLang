# ModelLang 0.10 unstable evolution boundaries

The following remain undefined or require manual migration review:

- field or entity removal;
- type conversion, narrowing, precision/scale change, or currency change;
- optional-to-required changes;
- default, annotation, generation, mutability, or snapshot-policy changes;
- arbitrary backfill expressions or user-written migration blocks;
- online/non-blocking DDL and large-table lock budgeting;
- index creation beyond constraints already generated by the language;
- invariant or exclusion additions to populated entities;
- enum-member rename, removal, reordering semantics, or stored-value transformation;
- workflow state removal, edge replacement, initial-state change, or physical rename;
- action/query semantic replacement under an existing stable ID;
- branching, merging, squashing, down migrations, and rollback generation;
- migration orchestration across services, tenants, regions, or database clusters;
- automatic compatibility checks for independently deployed frontend or API clients;
- schema evolution for database backends other than PostgreSQL.
