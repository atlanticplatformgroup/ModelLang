# ModelLang 0.37 unstable boundaries

Extension invocation, generated stubs, implementation discovery, deployment verification, test execution, package checksums, signed attestations, source fetching, secret configuration, latency budgets, structured failures, compensation workflows, extension-to-extension calls, runtime health, ownership directories, promotion automation, public extension discovery, and extension capabilities remain outside the stable contract.

Target profile v1 describes only the canonical PostgreSQL/HTTP/UI generator. Alternate databases, transports, languages, UI frameworks, policy engines, workflow engines, MCP targets, agent targets, and cross-target behavioral conformance suites remain future work.

The extension ledger records declared obligations; it does not prove that an implementation exists, matches its contract, enforces authorization, runs its tests, or has been deployed. The host remains responsible for those obligations. The target report is deterministic assurance metadata and grants no authority.
