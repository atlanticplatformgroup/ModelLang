# ModelLang 0.36 unstable boundaries

The following remain outside the stable read contract: arbitrary caller-selected fields or directions, compound authored sort keys, nullable sort fields, offset or page-number pagination, caller-controlled page size, cursor signing or encryption, frozen cross-request snapshots, as-of or historical reads, freshness lifetimes, cross-transaction snapshot guarantees, externally signed evidence, public evidence lookup, audit observation APIs, audit retention or deletion policy, denied-read audit, collection or reverse traversal, inferred joins, runtime-selected projection paths or depth, aliases, computed fields, inline anonymous shapes, conditional key omission, redaction reason payloads, per-field authorization traces, runtime field selection, collection-member disclosure, nested-row-scoped conditions, aggregates, grouping, full-text search, caching, field-level capability negotiation, MCP-specific result contracts, and generic CRUD.

Transactional read evidence proves only what committed generated database state records. Because PostgreSQL has no autonomous transaction in this profile, a client may receive a result inside an explicit transaction and later roll that transaction back; no durable evidence remains for that uncommitted invocation. ModelLang does not call that a committed audited read. Evidence hashes are integrity bindings, not signatures, attestations, non-repudiation proofs, or authorization grants.

The audit table is private deployment-owned state. This release provides no application or operator observation surface and prescribes no retention window. Hosts remain responsible for transaction completion, backup, access control above the generated PostgreSQL roles, and any external compliance interpretation.
